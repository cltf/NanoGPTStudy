2.1 人话版：Embedding / Attention / MLP

人话版 Embedding / Attention / MLP —— Transformer 三大块

Embedding：把文字变成数字向量；Attention：让文字互相「看得到彼此」（在 GPT 里只能看前面）；MLP：对每个位置单独做思考加工。三块合起来就是 Transformer 的基础能力，也是 NanoGPT 的核心。

①Embedding 嵌入

通俗说：翻译器——把 token（字符 / 词元）变成一串数字向量。

  • 计算机不能直接看懂 A、B、我、love，只能算数字
  • 词表里每一个字符，对应一个固定长度的向量（你这边是 128 维一串小数；大模型常见 512 / 768 / 4096…）
  • 还有位置嵌入 Positional Embedding：告诉模型「这个字在第几个位置」——因为 Attention 本身不自带先后顺序
例子 字符 R → 查表得到向量 [0.21, -0.33, 0.75, ...]（长度 = n_embd）

作用：文字 → 数字，作为模型输入。

两处容易误会（已修正）
  • 「语义相近的 token 向量更近」——这是训练之后逐渐学出来的；刚初始化时向量几乎是随机的，谈不上语义。
  • 这里的 embedding 是模型内部输入层，不是检索用的「文本向量模型」。原理都是「映射到向量空间」，用途不同。

②Attention 自注意力（Self-Attention）

通俗说：让每个 token 去看上下文里其他 token，判断哪些字对自己很重要。像阅读时每个字都在扫整段话、抓关联。

指代例子（从左往右读时） 「它把杯子摔了，它碎了」
第二个「它」可以看向前面的「杯子」（前文），从而偏向理解为杯子碎了。

每个位置会分出三组向量：

Query（查询）
我这个词，想找什么样的伙伴
Key（键）
所有词对外展示的特征
Value（值）
所有词携带的、真正要传出去的信息
  • Query 和 Key 算相似度（打分）
  • Softmax 变成权重：哪些词更相关
  • 用权重对 Value 加权求和 → 融合上下文后的新向量

多头注意力 Multi-head：同时开多组独立「阅读通道」（你设 n_head=4）。一组可能偏语法、一组偏指代、一组偏搭配，最后拼在一起。

作用：抓取上下文关系、长距离依赖。

对 NanoGPT / GPT 极其重要

GPT 是单向自注意力（因果掩码 causal mask）：一个 token 只能看前面的文字，看不到后面，正好匹配「自回归预测下一个 token」。BERT 类双向模型可以左右都看——和 GPT 不同。

③MLP（Multilayer Perceptron） 多层感知机

通俗说：独立的小神经网络，给每个位置单独思考、加工信息。

  • Attention 之后，每个 token 已经收集好上下文，还需要非线性变换把信息消化、提炼
  • 对每一个位置的向量单独跑一遍；位置之间互不干扰（跨位置交换信息是 Attention 的活）
  • 一般结构：升维 → 激活（如 GELU）→ 降维。你这边大致是 128 → 512 → 128

教材常说：Attention =「收集信息」，MLP =「思考消化信息」。作用：非线性加工、提炼，也承担一部分「编码知识」的能力。

④串起来：NanoGPT 真实顺序

注意：Embedding 只在入口做一次，不是每一层都做 输入 token
→ Embedding（文字→数字）+ 位置信息  ← 只此一次
→ 重复 n_layer 次 Block：【多头自注意力】→【MLP】（每步还有 LayerNorm + 残差）
→ 最后 lm_head 得到 logits → Softmax + 交叉熵算 loss

你调过的 n_layer（如 4）= Block 叠多少层。

⑤极简比喻（因果版，已改对）

读片段：Romeo speak（从左到右生成时）

  • Embedding：把每个字译成一串数字笔记
  • Attention（单向）：speak 可以看前面的 Romeo，知道「谁在说话」；但 Romeo 不能看后面的 speak（那是未来，被 causal mask 挡住）
  • MLP：各位置在自己内部加工已收集到的信息
  • 多层堆叠后输出：下一个字符更可能是什么
常见错说法（不要记）

「Romeo 看后面的 speak，知道主谓关系」——这是双向注意力的直觉，不符合 GPT / NanoGPT。自回归生成时，前面的词在被写下的那一刻，后面的词还不存在。

⑥区分重点，防止搞混

模块一句话跨位置？
Embedding文字→数字，输入层否（查表）
Attentiontoken 之间通信、找关联是（GPT 里只向前文）
MLP单个 token 内部运算思考否

2.3 Embedding：离散字符 → 连续向量

model.py 中的核心三行：

tok_emb = self.transformer.wte(idx)   # (B, T, n_embd)
pos_emb = self.transformer.wpe(pos)   # (T, n_embd)
x = self.transformer.drop(tok_emb + pos_emb)
  • wte：查表，每个字符 ID → n_embd 维向量（你训练轻量版是 128）
  • wpe：位置 0,1,2… 也各有一个向量
  • 相加：同一个 'l' 在 Hello 的第 3、4 位，表示不同（位置不同）
通俗版：名片 + 印章

把这块想成：先给每个字发一张名片，再盖一个「第几位」的印章，两样叠在一起交给后面的网络。

1）计算机眼里先是编号，不是字母

Hello → ID H e l l o
↓ ↓ ↓ ↓ ↓
20 43 50 50 53

这些只是编号，还不能直接算，要用 Embedding 查表换成一串小数。

2）wte = 字的名片（Token Embedding）

词表里每个字符都有一张固定长度的名片。你训练时长度是 128（演示脚本写成 8 只是好画）：

查表 查「H」→ [0.12, -0.44, 0.08, …] 一共 128 个数
查「e」→ [另一串 128 个数]
查「l」→ [又一串…]

同一字母、同一张名片：两个 l 查出来的字向量一开始是一样的。对应 tok_emb = self.transformer.wte(idx)。

3）wpe = 第几位的印章（Position Embedding）

光有字还不够：两个 l 一个在第 3 位、一个在第 4 位，角色不同。Attention 自己也不知道谁前谁后，所以再给每个位置盖一枚印章（位置 0、1、2… 各一串 128 个数）。对应 pos_emb = self.transformer.wpe(pos)。

4）为什么要相加？

x = tok_emb + pos_emb   # 每个位置：字的名片 + 位置印章
第 3 个 l第 4 个 l
字名片相同（都是 l）相同
位置印章位置 2 的位置 3 的
相加后不同不同

这样模型才能区分「Hello 里前一个 l / 后一个 l」。drop 只是训练时随机丢掉一点点，防死记硬背，理解时可先忽略。

5）(1, 5, 8) 是什么意思？

别被括号吓到，就是「小表格」的尺寸：

形状 = (batch大小, 有几个字, 每个字几维小数) 演示 Hello： (1, 5, 8) → 1 句话、5 个字、每字 8 个数
你真训练时约：(64, 256, 128) → 同一件事，只是更大

三句话：wte 这个字是谁 → 查名片；wpe 站在第几位 → 盖印章；相加 后才是 Attention / MLP 真正拿去算的东西。

形状直觉

输入文本 Hello（T=5），演示脚本用 n_embd=8 时：tok_emb 形状为 (1, 5, 8)，即 batch×序列长度×向量维度。

2.4 Attention：让每个位置「看见」前文

核心公式：

$$\mathrm{Attention}(Q,K,V)=\mathrm{softmax}\!\left(\frac{QK^{\top}}{\sqrt{d}}\right)V$$
符号含义
$Q$（Query）我在找什么
$K$（Key）我有什么可被找
$V$（Value）真正传出去的内容
$\sqrt{d}$防止点积过大，Softmax 变得过于尖锐
Causal Mask右上角置 $-\infty$，不能偷看未来字符

对应代码（慢速路径便于阅读；MPS 上常走 flash 路径，数学等价）：

att = (q @ k.transpose(-2, -1)) * (1.0 / math.sqrt(k.size(-1)))
att = att.masked_fill(self.bias[:,:,:T,:T] == 0, float('-inf'))
att = F.softmax(att, dim=-1)
y = att @ v

结构上的「自回归保证」

预测第 $t$ 个字符时，只能用位置 $0..t$ 的信息。这不是训练技巧，而是模型结构强制的——和采样时「一个字一个字往后吐」完全对齐。

2.5 Block = Attn + MLP + 残差

每个位置进来是一个向量（你这边 128 维），经过一层后还是 128 维，但内容被「更新」过：

def forward(self, x):
    x = x + self.attn(self.ln_1(x))
    x = x + self.mlp(self.ln_2(x))
    return x
一层 Block 数据流
x ──► LayerNorm ──► Attn ──► 加回 x
  ──► LayerNorm ──► MLP  ──► 加回 x
残差是什么意思？

残差（residual）就是代码里的「加上原来的 x」：

x = x + self.attn(...)   # 不是用 Attn 结果直接换掉 x
x = x + self.mlp(...)    # 而是：旧的 x + 本层算出的增量

名字来自「残差 ≈ 差值」：本层主要学要在原表示上改多少，而不是从零重写整份表示。

写法像什么
没有残差：x = Attn(x)每层把笔记整页撕掉重写
有残差：x = x + Attn(x)在原稿上贴便利贴（增量修改）

为什么要这样？

  • 好训练：梯度可以顺着「+」那条直路回传，深层不容易训不动
  • 好叠加：n_layer=4/6 甚至更深都能堆，每层只负责「再改一点」
  • 更稳：一层就算学得一般，至少还保留输入本身

一句话：残差 = 输出 = 输入 + 本层增量；Attn/MLP 负责「改什么」，残差负责「别把旧的弄丢」。

Attn = Attention（注意力）

干什么：让不同位置互相交换信息。例如预测下一个字时，当前位置可以去「看」前面的 ROMEO、:、换行等，按相关程度加权汇总。

  • 用 Q / K / V 算「谁该看谁」
  • 有 Causal Mask：不能看未来字符
  • 你设了 n_head=4：同一层 4 组注意力，从不同角度看前文，再拼起来

一句话：Attn 管「位置之间」——谁和谁有关。类比：开会时听别人发言。

MLP = 多层感知机

干什么：每个位置自己做非线性变换，不和别的位置说话。

# nanoGPT 里的 MLP
# 128 → 512（4×n_embd）→ GELU → 512 → 128
self.c_fc    # 扩维
self.gelu    # 非线性
self.c_proj  # 压回 n_embd

一句话：MLP 管「位置内部」——把当前向量特征再加工。类比：听完后自己整理笔记。

AttnMLP
全称Attention / 自注意力Multi-Layer Perceptron
作用范围多个位置之间单个位置内部
直观看前文、选重点想一想、变换特征
类比开会听别人发言听完后整理笔记
模块分工
Attention位置之间交换信息（例如学会「Citizen 后常跟冒号」）
MLP每个位置自己做非线性变换（扩到 $4\times n_{embd}$ 再压回）
残差 x + …深层梯度可回传；每层只学「增量修正」
LayerNorm稳定激活分布，让训练更稳

你训练时 n_layer=4，就是把这个 Block 叠 4 次。整条链路：

字符 → Embedding(128维)
  → [Attn + MLP] × 4     ← n_layer 个 Block
  → lm_head → 65 个 logits → Softmax → 概率

训练命令里的参数说明见 第1章 · Attn 和 MLP。

2.6 lm_head：向量 → 65 个分数

logits = self.lm_head(x)   # (B, T, vocab_size)
loss = F.cross_entropy(...)

每个位置输出 65 维 logits，再进入第1章的 Softmax 与 Cross-Entropy。

通俗版：阅卷老师打分

前面 Embedding / Attention / MLP 忙了半天，每个位置手里拿着一叠「读后笔记」（128 维向量 x）。 lm_head 就像阅卷老师：对照词表里 65 个候选字符，给每个候选打一个分——谁分高，模型就更觉得「下一个该是它」。

某一个位置上的输出（示意） 候选：\n   空格   !   …   R   …   z
分数：1.2   0.3   -0.5   …   3.8   …   -1.1
→ 一共 65 个数 = logits（还不是概率）
  • 为什么是 65？词表就 65 个字符，老师要对每个可能的「下一字」都打分，一个都不能少。
  • 怎么从 128 维变成 65 分？一次线性变换（矩阵乘法）：用 65 把「尺子」去量这叠笔记，每把尺子量出一个分数。公式就是第1章写的 $\mathrm{logits}=x W^{\top}$。
  • 接下来呢？Softmax 把分数收成 0~1 的概率；再和标准答案比，用 Cross-Entropy 算 loss——「正确答案那个字，你给的概率够不够大」。

整句话串起来：

前向最后两步 读后笔记 x（128维）
→ lm_head 打出 65 个分（logits）
→ Softmax 变概率 → 和真实下一字符比 → 得到 loss

训练时每个位置都要打分（好算整段 loss）；生成时通常只看最后一个位置的 65 分，再采样吐出下一个字符。

和 model.py 的速查对应（加了人话）

左边是「在干什么」，右边是「代码在哪」——对照着翻 model.py 即可。

人话数学/模块代码位置

每个位置自己消化信息 残差 + MLP Block.forward

2.7 Softmax：原始分数 → 合法概率

一句话：Softmax 把一堆随便的原始分数，换成总和为 1 的相对概率；分数越高，分到的概率越大。

$$\boldsymbol{\sigma}(\boldsymbol{z})_i = \frac{e^{z_i}}{\sum_{j=1}^{K} e^{z_j}}$$
$\boldsymbol{z}$
输入，就是 logits：一组可正可负、可大可小的原始分数
$K$
候选总数。NanoGPT 字符版 $K=65$（词表 65 个字符）
$e^{z_i}$
自然指数，$e\approx 2.71828$，把分数都变成正数
分母
把全部 $e^{z_j}$ 加起来做归一化
输出特点 ①
每个值都在 $(0,1)$

可以当成「概率」来读

输出特点 ②
全部加起来 $= 1$

合法概率分布（不会出现概率和超过 100%）

Deep Dive 手算例子 + 两个重要特性 + 工程细节

①手工例子（$K=3$）

假设 logits：$z=[2,\ 1,\ 0]$

三步走 ① 指数：$e^2\approx7.389$，$e^1\approx2.718$，$e^0=1$
② 分母：$7.389+2.718+1=11.107$
③ 相除：$p\approx[0.665,\ 0.245,\ 0.090]$，总和 $=1$ ✔

含义：模型认为第 1 个候选概率最高。

②特性：相对大小会被放大

logits 差距一大，概率会更「一边倒」。例如 $z=[5,\ 0,\ 0]$ 时，第一个的概率会非常接近 1——高分被指数「拉得更远」。

③特性：不怕负数

例如 $z=[-1,\ -2,\ -3]$：

负数也能算 $e^{-1}\approx0.368$，$e^{-2}\approx0.135$，$e^{-3}\approx0.050$
总和 $\approx0.553$ → $p\approx[0.665,\ 0.244,\ 0.091]$

不会报错。有趣的是：这组和 $[2,1,0]$ 几乎同分布——因为 Softmax 只看相对差，整体加减同一个数，概率不变。

④工程细节：数值稳定版（PyTorch 内部用）

若某个 $z_i$ 很大，$e^{z_i}$ 可能直接爆成无穷大。实际实现会先减去本组最大值：

$$\sigma(z)_i=\frac{e^{z_i-\max(z)}}{\sum_j e^{z_j-\max(z)}}$$

数学结果不变，但不容易溢出。

⑤和 NanoGPT 的关系

loss = F.cross_entropy(logits, targets)

PyTorch 的 cross_entropy 内部自带 Softmax，训练时你不用再手写一遍。

若自己拆开写，等价于：

probs = torch.softmax(logits, dim=-1)
loss = -torch.log(probs[正确类别的位置])

这就是第1章的交叉熵 / NLL。

2.8 扩展：和现代 LLM 结构的对照

NanoGPT 的 Decoder-only Transformer 与今天主流 LLM（如 Llama / Qwen 一类）同属一族。阅读开源模型配置时，可主动寻找这些对应物：

  • n_embd / hidden size：向量宽度
  • n_head / num attention heads：注意力头数
  • n_layer：堆叠多少个 Block
  • RoPE 等位置编码：替换或增强本节的绝对位置嵌入

先掌握本节的「因果自注意力 + MLP + 残差」，再去看旋转位置编码、GQA、SwiGLU，会是增量学习，而不是从零重来。
