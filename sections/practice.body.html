A.2 数据：莎士比亚字符级

python data/shakespeare_char/prepare.py
  • 自动下载文本 → 写出 train.bin / val.bin / meta.pkl
  • 词表 65 个字符（语料里实际出现过的集合，不是全 ASCII）
  • train ≈ 100 万 token，val ≈ 11 万 token
上面三句话 · 通俗版

①「自动下载 → 写出三个文件」在干什么？

剧本原文是给人看的 .txt。模型更喜欢「已经编好号的二进制」。

文件像什么里面大概是什么
train.bin练习题册训练用的字符 ID 序列（一大串 0–64 的数字）
val.bin摸底考卷验证用的字符 ID 序列（训练时不拿它来改权重）
meta.pkl密码本「字符 ↔ 编号」对照表，以及词表大小=65

例子：字母 R 可能编成某个整数；整部剧就变成一长串整数，存进 bin。

②「词表 65 个字符」是什么意思？

词表 = 模型认识的「字」的清单。这里是字符级：每个英文字母、标点、换行都算一个字。

  • 脚本扫完整本莎士比亚文本，把出现过的字符收进清单 → 刚好 65 种
  • 不是「电脑里所有 ASCII 字符」；剧本里没出现的（比如很多数字）就不进词表
  • 所以模型每次猜下一个字，只在这 65 个里选（见 第1章词表）

③「train ≈ 100 万 token，val ≈ 11 万 token」？

在这个项目里，一个 token = 一个字符（不是英文单词）。

举例 文本 "Hi!" → 3 个 token：'H'、'i'、'!'
  • train ≈ 100 万：练习册大约有一百万个字符，用来天天练、改参数
  • val ≈ 11 万：另外留出约十一万个字符当考试；算 val loss 用，不拿来更新权重
  • 大约九成训练、一成验证——就是你曲线上蓝线 / 橙线各自用的数据
这些文件是怎么生成的（prepare.py）

一条命令搞定：

python data/shakespeare_char/prepare.py
流程图 网上莎士比亚 txt
→ ① 下载（若本地还没有）→ input.txt（人可读原文）
→ ② 统计出现过的字符 → 65 个
→ ③ 建 stoi / itos 对照表
→ ④ 前 90% / 后 10% 切开
→ ⑤ 字符 → 整数 ID，写成二进制
→ train.bin   val.bin   meta.pkl
  1. 下载原文 → input.txt
    本地没有就从 GitHub 拉 tinyshakespeare；有了就直接读。你在 IDE 里打开的就是这一步的结果。
  2. 扫全文得到 65 字符词表
    chars = sorted(list(set(data))) → 去重 + 固定顺序；不是全 ASCII。
  3. 建编码表
    stoi：字符→ID；itos：ID→字符（0–64）。
  4. 切成 train / val
    train_data = data[:int(n*0.9)]，val_data = data[int(n*0.9):] —— 同一部剧按长度切开，不是随机打乱句子。
  5. 编码并写出三个文件
    每个字符换成整数 → np.uint16 → tofile 成 bin；词典等写入 meta.pkl。
产出怎么来的
input.txt下载/读取的原文
train.bin前 90% 文本 → ID 列表 → uint16 落盘
val.bin后 10% 同理
meta.pkl保存 stoi / itos / vocab_size，采样时用来解码

一句话：prepare.py = 下载剧本 → 建 65 字符词典 → 按 9:1 切开 → 字符换成数字存 bin，词典存 pkl。

train.bin / val.bin 里面是什么？如何查看？

两者格式一样：一长串 uint16 整数（每个 = 一个字符 ID，范围 0–64）。差别只在截自原文的哪一段。

文件内容规模（你本机）
train.bin剧本前约 90% 的字符 ID1,003,854 个 ID ≈ 2MB
val.bin剧本后约 10% 的字符 ID111,540 个 ID ≈ 0.2MB

用 meta.pkl 解码后，开头大约是：

解码预览 train → First Citizen: Before we proceed...
val   → GREMIO: Good morrow, neighbour Baptista...

用编辑器直接打开 bin 会像乱码——那是二进制。人读原文请打开 input.txt；看编号版用下面脚本。

cd "~/大模型训练/nanoGPT"
source .venv/bin/activate

python - <<'PY'
import pickle, numpy as np

with open("data/shakespeare_char/meta.pkl", "rb") as f:
    itos = pickle.load(f)["itos"]

# 改成 val.bin 可看验证集
data = np.memmap("data/shakespeare_char/train.bin", dtype=np.uint16, mode="r")

print("长度:", len(data))
print("前30个ID:", list(map(int, data[:30])))
print("解码:")
print("".join(itos[int(i)] for i in data[:500]))

A.3 第一轮训练：轻量版 v1

目的：几分钟内看完 loss 下降 + 学会整条命令。

python train.py config/train_shakespeare_char.py \

项结果

产物out-shakespeare-char/ckpt.pt + loss_curve.png

A.4 第二轮训练：加强版 v2

因 v1 采样「很差」属预期（太小太短），再用配置文件默认更大模型训满 5000 步。

python train.py config/train_shakespeare_char.py \
  --device=mps --compile=False \
  --out_dir=out-shakespeare-char-v2
项结果
参数量约 10.65M（6 层 / n_embd=384）
耗时约 24 分钟
终点train ≈ 0.63，val ≈ 1.70
曲线约 1500–2000 步后 train↓ val↑ → 典型过拟合
采样比 v1 更像剧本英语，仍有拼写错误（字符级小模型上限）
过拟合（结合本轮实验）

过拟合 = 训练集越来越熟（train loss↓），验证集反而变差（val loss↑）——像练习册满分、摸底考掉分，模型在「背题」。

你的 v2 曲线后半段就是教科书例子。详解与应对见 第5章 · 什么是过拟合， 读图见 训练曲线解读。
