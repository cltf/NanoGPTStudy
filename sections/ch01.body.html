1.2 数学：自回归分解

整段文本的概率被拆成「每一步预测下一个」：

$$P(x_0,x_1,\ldots,x_T)=\prod_{t=0}^{T} P(x_t \mid x_{<t})$$

训练目标 = 最大化这个似然 = 最小化负对数似然（NLL）：

$$\mathcal{L}=-\sum_t \log P_\theta(x_t \mid x_{<t})$$
Deep Dive 把上面两个公式讲成人话

①先看第一个公式：自回归分解

$$P(x_0,x_1,\dots,x_T)=\prod_{t=0}^{T} P(x_t \mid x_{<t})$$
$P(A)$
A 这件事发生的概率
$P(x_t \mid x_{<t})$
条件概率：在已经看到前面所有文字 $x_0,x_1,\ldots,x_{t-1}$ 的前提下，下一个是 $x_t$ 的概率
$\prod$（连乘）
把每一步的概率全部乘起来

一整段文字出现的总概率 = 依次把「每一步猜对下一个 token 的概率」相乘。

极简例子 · 句子 I love cat 总概率 = P(I) × P(love | I) × P(cat | I love)

模型就是要让这个总概率尽可能大。

②什么是「似然（Likelihood）」

似然：给定模型参数，观察到这串文本的概率。

概率 Probability
固定模型 → 问文字

「这个句子出现的可能性有多大？」

似然 Likelihood
固定真实句子 → 评模型

「当前这套参数，有多符合真实数据？」

通俗理解：似然 = 模型猜中真实文本的「靠谱程度」。似然越大，模型越贴合真实数据。

重点区分
  • 概率：从模型 → 预测文字
  • 似然：从真实文字 → 评价模型好不好

训练目标：最大化似然，让模型认为真实文本发生的概率尽可能高。

③第二个公式：负对数似然 NLL（就是 Loss）

$$\mathcal{L}=-\sum_{t} \log P_\theta(x_t \mid x_{<t})$$

为什么要把「最大化似然」转成「最小化 loss」？两个数学原因：

  • 一堆小数相乘会极小，计算机容易下溢；取 $\log$ 后乘法变加法，更好算
  • $\log$ 特性：概率越大，log 值越大；框架习惯最小化损失，所以前面加负号 $-$
最大化似然 ⇔ 最小化负对数似然（NLL Loss）
$\theta$
模型里所有权重（权重文件里那一大堆数字）
$\mathcal{L}$
就是你训练时看到的 loss

loss 越小 = 负对数似然越小 = 似然越大 = 模型预测下一个 token 越准

④结合你跑过的 NanoGPT

莎士比亚字符 GPT，和 ChatGPT 预训练的数学公式完全一样：

  • NanoGPT：预测下一个字符（char）
  • ChatGPT / Gemma / Qwen：预测下一个词元（token）

差别只在：分词方式、参数量、训练数据大小；底层目标相同。

⑤生活化小结

假设句子是：今天天气很好

自回归连乘 P(今) × P(天|今) × P(天|今天) × P(气|今天天)
× P(很|今天天气) × P(好|今天天气很)
  • 似然：模型给这一串的总打分，打分越高越好
  • 训练：不断调整权重，拉高这个打分；等价于降低 loss

你看到 loss 持续下降，本质就是：模型的似然在不断变大——它越来越会猜下一个字。

1.3 Loss 到底是什么数？

模型输出每个字符的分数 logits（长度 65），再 Softmax 成概率：

$$P(c)=\dfrac{e^{z_c}}{\sum_{c'} e^{z_{c'}}}$$

若正确答案是字符 $c^*$：

$$\text{CrossEntropy}=-\log P(c^*)$$
Deep Dive Logits → Softmax → CrossEntropy 拆开讲

①logits 是什么

模型最后输出一堆没有范围限制的原始分数，就叫 logits。

你这个 NanoGPT 莎士比亚字符版，词表一共 65 个字符（完整列表见上方），所以每次输出 65 个分数。

这些分数不是概率！可以是正数、负数、大或小，没法直接理解成「可能性」。

示例（示意数字，不是某次真实打印） logits = [2.3, 0.1, -1.2, ...] 一共 65 个数字
每个数字 = 模型对「下一个字符是这个候选」的偏好打分

①+这 65 个数是怎么算出来的

不是手写的，而是前向传播最后一步：线性层 lm_head 算出来的。

对某一个位置（例如刚看完前文，要猜下一个字符）来说：

  • 前面整网先算出语义向量 $x$：字符 ID → Embedding(+位置) → 若干层 Attention/MLP → LayerNorm。你训练时 n_embd=128，所以 $x$ 是 128 维
  • lm_head 做线性变换：把 128 维映射成 65 维分数（无 bias）
128 维怎么来的？

不是从数据里算出来的，而是训练时你手动设的超参数 n_embd。

当时轻量命令里写了：

--n_layer=4 --n_head=4 --n_embd=128 --max_iters=1500

配置文件默认其实是 n_embd=384，被命令行覆盖成了 128。含义是：每个位置用 128 个数描述当前语义，整条网络都按这个宽度设计。

环节与 128 的关系
wte 词嵌入形状 (65, 128)：每个字符 → 一个 128 维向量
wpe 位置嵌入每个位置也是 128 维，与词向量相加
Attention / MLP通道数保持 128（多头时每头 128/4=32 维）
lm_head形状 (65, 128)：用 128 维点积出 65 个分数
65
词表大小

语料里出现过多少种字符 → logits 有多少个候选

128
n_embd（你设的）

中间表示有多「宽」：越大通常越强，也更吃算力

选 128 是为了快速跑通；改成 384 也能训，只是更慢、模型更大。

③ 模型结构

参数含义你设的配置默认
--n_layerTransformer Block 叠多少层（每层 = Attn + MLP）46
--n_head每层注意力头数（多视角看前文）46
--n_embd隐藏向量宽度128384

约束：$n\_embd \bmod n\_head = 0$。你这里 $128\div4=32$，每头 32 维，合法。

  • n_layer ↑ → 更深，更慢、参数更多
  • n_head ↑ → 同层更多「视角」（总宽度仍由 n_embd 限制）
  • n_embd ↑ → 表示更强，显存/算力开销更大
Attn 和 MLP 是什么？

每一层 Transformer Block = Attn + MLP（外加 LayerNorm 与残差）。你设 n_layer=4 就是把下面这套叠 4 次。

一层 Block 数据流 x ──► LayerNorm ──► Attn ──► 加回 x
   ──► LayerNorm ──► MLP  ──► 加回 x
Attn = Attention
位置之间换信息

当前位置按相关程度「看」前文（如 ROMEO、:、换行）。有 Causal Mask，不能看未来。n_head=4 表示 4 组注意力并行看。

管「谁和谁有关」 · 类比：开会听别人发言

MLP = 多层感知机
位置内部做变换

每个位置单独：128 → 512（4×n_embd）→ GELU → 压回 128。不和别的位置说话。

管「自己加工特征」 · 类比：听完后整理笔记

残差 x + …：本层只学修正量，梯度好回传，才能叠很多层。更细的公式见 第2章。

参数含义你设的配置默认
--max_iters训练多少个 step 后停止15005000

每 1 个 iter ≈ 一个 batch：前向 → loss → 反向 → 更新。你当时约 $64\times256=16384$ 次「猜下一字符」/步。

为什么刚好是 65 个？不是算出来碰巧是 65，而是 lm_head 的输出维度被设成 vocab_size=65——词表有多少字符，就输出多少分。

下标含义

下标 1 → 空格的偏好
…
下标 64 → 字符 z 的偏好

训练在改什么

开始时 $W$ 接近随机 → logits 乱 → loss≈4.17
训练后正确字符的 logit 被抬高 → Softmax 后 $P(c^*)$ 变大 → loss 下降

极小例子（帮助理解「点积打分」；词表暂设为 A/B/C，$n_{\mathrm{embd}}=2$）：

手算演示 x = [1.0, 0.5]
W_A=[2.0, 0.6] → z_A = 1×2 + 0.5×0.6 = 2.3
W_B=[0.0, 0.2] → z_B = 0.1
W_C=[-1.0, -0.4] → z_C = -1.2
⇒ logits = [2.3, 0.1, -1.2] 再 Softmax 才变成概率
张量（你真实配置）形状含义
隐藏状态 x(64, 256, 128)batch × 位置 × 向量维
lm_head 权重(65, 128)65 个字符各一条 128 维「探针」
logits(64, 256, 65)每个位置对 65 个字符各打一分

笔记里的 [2.3, 0.1, -1.2, ...] = 其中某一个位置那一行 65 个数的示意。

②Softmax：把 logits 转成概率

$$P(c)=\frac{e^{z_c}}{\sum_{c'} e^{z_{c'}}}$$
$z_c$
第 $c$ 个候选字符的 logit 分数
$e^{z_c}$
指数函数，把分数全部变成正数
分母 $\sum_{c'} e^{z_{c'}}$
把全部 65 个候选的指数结果加起来，做归一化

结果：得到 65 个 0~1 之间的概率，总和 = 1，变成合法概率分布。

词表只有 3 个字符 A / B / C 时 logits = [3, 1, 0]
e³≈20.08，e¹≈2.72，e⁰=1
总和 = 20.08+2.72+1 = 23.8
P(A)=20.08/23.8≈0.84，P(B)≈0.11，P(C)≈0.05
→ 模型觉得下一个是 A 的可能性最高

③CrossEntropy 交叉熵

$$\text{CrossEntropy}=-\log P(c^*)$$
$c^*$
真实正确的那个字符（标签 / 标准答案）
$P(c^*)$
Softmax 之后，模型分配给【正确答案】的概率
模型很准
$P(c^*)$ 接近 1

$\log(1)=0$ → loss ≈ 0

模型很瞎
$P(c^*)$ 很小（如 0.01）

$\log(0.01)\approx-4.6$ → 加负号，loss ≈ 4.6

loss 越大 = 模型猜错得越离谱

④和上一节公式串起来

上一节的总损失：

$$\mathcal{L}=-\sum_{t} \log P_\theta(x_t \mid x_{<t})$$
  • 每一个位置 $t$，就是这里的 $-\log P(c^*)$
  • 把所有位置的交叉熵加在一起，就是整个句子的总损失
在 next-token 预测场景：交叉熵损失 = 负对数似然 NLL

对应 model.py：

logits = self.lm_head(x)
loss = F.cross_entropy(
    logits.view(-1, logits.size(-1)),
    targets.view(-1),
    ignore_index=-1
)

完整流水线（务必分清顺序）

1
logits每个字符一个原始分数（可正可负）
2
Softmax变成概率，所有字符概率和为 1
3
取正确答案的概率 P已经是概率了，不要再 Softmax
4
loss = −log(P)P 越大，loss 越小
易错点

若题目说「正确答案概率已经是 0.5」，直接算 $-\log(0.5)\approx 0.693$。不要写成 $-\log(\mathrm{softmax}(0.5))$——Softmax 作用在 logits 上，不是作用在概率上。

1.4 和你训练曲线的对照

现象数值含义
完全瞎猜 65 类 $\log 65 \approx 4.174$ 随机基线
你的 step 0 loss ≈ 4.19 几乎等于随机猜
你的 step 1500 train ≈ 1.59 / val ≈ 1.78 平均 $P\approx e^{-1.59}\approx 20\%$（从 1.5% 涨上来）；尚未明显过拟合
记忆口诀
  • loss 小 → 模型给正确答案的概率大 → 学得越好
  • loss 大 → 几乎没把概率分给正确答案
  • 训练目标 = 最小化平均 Cross-Entropy（最大似然）
  • 只看 train 下降不够 → 还要盯 val（见第5章）

1.5 每个训练 step 在优化什么

你的配置：batch_size=64，block_size=256

$$64 \times 256 = 16{,}384$$

每一步同时做 16384 次「猜下一个字符」，把这些位置的 CE 平均起来，就是终端里打印的 loss。然后：算梯度 → AdamW 更新参数 → 下一轮再猜。

1.6 扩展：从小模型到大模型，不变的是什么

字符级莎士比亚和千亿参数大模型，表面上差很远，但训练目标同构：

  • 都在最大化「下一个 token」的似然（等价于最小化交叉熵 / NLL）
  • 都把离散符号变成向量，再经深层网络打出词表上的 logits
  • 评估时同样要同时看 train 与 held-out（val/test）曲线

差别主要在：词表更大（子词 BPE）、上下文更长、层数与宽度更大、数据与算力工程更复杂。先把 NanoGPT 这条最小闭环吃透，再看大模型论文时会轻松很多。

自测题

Q1：为什么 step 0 的 loss 会接近 4.17？

参考答案：刚开始参数接近随机，Softmax 后各字符概率约 $1/65$，故 loss ≈ $\log 65$。

Q2：若正确答案概率是 0.5，这一位的 loss 是多少？

参考答案：$-\log(0.5)\approx 0.693$（概率已就绪，不再 Softmax）。
