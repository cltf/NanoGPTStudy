简明总览

大模型是怎么训练出来的

一句话：给模型看海量文字，让它不断练习「猜下一个词」；猜错了就改参数，猜对了就强化——练到很会猜为止。

1. 训练在干什么？

不是背百科全书，而是学语言规律：

看见：今天天气很
目标：提高「晴 / 好 / …」这些合理续写的概率
手段：用 loss（误差） 衡量猜得有多差，再反向改权重

预训练阶段几乎都是这个目标（Next Token Prediction）。后面的微调，只是换数据、改行为，数学循环往往还是同一套。

2. 一次训练迭代长什么样？

可以当成工厂流水线，转了几十万圈：

  1. 取数据：从语料里拿出一小批文本，切成 token（词/字片）。
  2. 正向计算：Embedding → 多层 Attention + MLP → 得到词表上每个词的分数（logits）。
  3. 算 loss：和「真正的下一个 token」比，通常用交叉熵——错得越离谱，loss 越大。
  4. 反向传播：算出每个参数该往哪边拧，才能让 loss 变小（梯度）。
  5. 优化器更新：AdamW 等按学习率改一点点权重。然后回到第 1 步。
你要盯的信号

train loss 下降 = 在学训练集；再看 val loss：若训练降、验证升 → 可能过拟合。评测集比只看 loss 更接近「好不好用」。

3. 详细例子：用一句话走完一轮训练

下面用玩具数字把一轮拆开。假装词表只有 4 个词，模型也很小——真实模型只是词表更大、层数更多，步骤一样。

3.1 准备数据

语料里有一句：

小猫睡着了

切成 token（这里按字）：

位置0123
字小猫睡着了*
ID0123

*例子里把「着了」当成一个 token，方便只算 4 个词。真实分词更碎。

训练时的游戏规则：

  • 看见前面的字 → 猜下一个字
  • 比如看见「小」「猫」→ 正确答案应该是「睡」
  • 看见「小」「猫」「睡」→ 正确答案应该是「着了」

3.2 只盯一个位置：猜「睡」

输入：已看到 小 猫（ID: 0, 1）
标准答案：下一个必须是 睡（ID: 2）

① 正向：模型给出 4 个词的「原始分数」logits（未训练好时胡猜）：

候选词小猫睡着了
logit1.02.00.50.2

模型当前更偏向猜「猫」（2.0 最高），但正确答案是「睡」——所以要挨罚。

② Softmax：分数 → 概率（总和为 1）

粗算后大约是：

词小猫睡着了
概率0.220.590.130.06

正确答案「睡」只有 13% 概率 → 猜得很差。

③ 交叉熵 Loss（只看正确答案那个概率）

loss ≈ −log(P(睡)) ≈ −log(0.13) ≈ 2.04
概率越低，loss 越大；若 P(睡)=0.9，loss 会小很多。

真实训练会对句子里每个位置都算一遍再平均；这里只演示一个位置。

④ 反向传播：算出「该怎么改权重」

自动微分会告诉每一层：为了让 P(睡) 变大、让 loss 变小，Embedding / Attention / MLP 里成千上万个小数该微调一点。
你不必手算；框架（PyTorch / MLX）会算梯度。

⑤ 优化器更新（如 AdamW）

新权重 ≈ 旧权重 − 学习率 × 梯度方向
学习率很小（如 1e-4），每次只拧一点点，避免一次改炸。

3.3 更新之后会发生什么？

再跑同一输入，理想情况变成：

词小猫睡着了
概率0.100.150.650.10

「睡」概率升高 → loss 变小。换下一批句子继续转这个圈，几万、几十万次后，模型就「会续写」了。

把例子放大到真实大模型

词表：4 个 → 几万～十几万
句子：1 句 → 海量网页/书/代码
层数：玩具几层 → 几十层 Transformer
每一步仍是：猜下一个 → 算 loss → 改权重

3.4 若这是 SFT 微调呢？

循环一模一样，只是数据换成对话，例如：

user：什么是冒烟测试？
assistant：【结论】……【步骤】……【注意】……

模型要学会：在这种提问后面，下一个该接的 token 更像你的标准答（而不是胡聊）。常只更新 LoRA 小补丁，底座大部分冻结。

4. 三大阶段（产品怎么炼成）

① 预训练 Pretrain

海量网页/书/代码，学通用语言与知识。
贵、久、数据脏一点也能炼出「底座」。

② 指令微调 SFT

高质量「问题→标准答」对话，学会听指令、固定格式。
数据少而精，常只训 LoRA 小补丁。

③ 对齐（可选）

DPO / RLHF 等：用「好答 vs 坏答」偏好，压胡话、跟人类偏好。
通常在 SFT 之后。

你本地的 NanoGPT 笔记 ≈ ① 的微型版；微调目录 ≈ ②③ 的实操线。

5. 一张图串起来

端到端 原始文本 / 对话数据
→ Tokenize（变成 ID）
→ 模型前向（猜下一个）
→ Loss
→ 反向 + 优化器（改权重）
→ 存 checkpoint
→（可选）SFT / DPO
→ 推理服务（vLLM 等）对外回答

6. 和推理的差别（别混）

训练推理
目标改权重，让 loss 降权重基本不动，快速生成
算什么正向 + 反向 + 优化器主要正向（+ KV Cache）
数据大批标注/语料用户当前 prompt
你关心loss、过拟合、数据质量延迟、吞吐、显存

7. 记住这四句就够

带走
  1. 训练 = 反复「猜下一个词 + 按误差改参数」。
  2. 一轮 = 数据 → 前向 → loss → 反向 → 更新。
  3. 产品路径 ≈ 预训练底座 → SFT 听话 →（可选）偏好对齐。
  4. 数据质量与评测，往往比盲目加参数更重要。
